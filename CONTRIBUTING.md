# Contributing to Weatherly

Thanks for taking the time to contribute.

## Ways To Contribute

- Report bugs
- Suggest improvements
- Improve documentation
- Fix issues
- Add tests or strengthen validation
- Refine UI, accessibility, or performance

## Before You Start

- Search existing issues and pull requests before opening a new one
- Keep changes focused and easy to review
- If your change is large, open an issue first so the direction can be discussed

## Local Setup

1. Install dependencies with `npm install`
2. Copy `.env.example` to `.env`
3. Add `OPEN_WEATHER_API_KEY`
4. Start local development with `npm run dev` or `npm run dev:vercel`

## Development Guidelines

- Follow the existing code style and file organization
- Prefer small, readable components and utility functions
- Keep API keys and secrets out of the client
- Update documentation when behavior or setup changes
- Run lint before opening a pull request

## Pull Request Checklist

- The change solves one clear problem
- Code is linted with `npm run lint`
- Documentation is updated if needed
- Screenshots or short notes are included for UI changes
- The pull request description explains what changed and why

## Reporting Bugs

Please include:

- What you expected to happen
- What actually happened
- Steps to reproduce
- Browser or environment details
- Screenshots or logs when helpful

## Suggesting Features

Feature requests are most helpful when they include:

- The problem you are trying to solve
- The proposed behavior
- Any tradeoffs or alternatives you considered
